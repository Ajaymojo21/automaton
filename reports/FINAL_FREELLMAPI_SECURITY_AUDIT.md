Two independent captures, both against the **compiled** code path (`dist/inference/provider-registry.js`)
or the real module, never against a hand-written substitute.

**a. `runtime/tmp/p20-p6-red.log` — 30-case hostile-URL probe.**
`SUMMARY: 30/30 hostile-or-edge URLs ACCEPTED`. Accepted set includes
`http://203.0.113.10/v1`, `http://<host-lan-ip>:3001/v1`, `http://10.0.0.5/v1`, `file:///etc/passwd`,
`data:text/plain;base64,…`, `http://user:password@localhost:3001/v1`, `http://localhost@evil.example/v1`,
`http://0x7f000001:3001/v1`, `http://0.0.0.0:3001/v1`. The `malformed-empty` case silently became
`https://api.openai.com/v1`. `overrideBaseUrl("openai","http://evil.example/v1")` → `ACCEPTED`.
A config file containing `{ this is not json` → `ACCEPTED silently, fell back to 4 default providers`.

**b. `runtime/tmp/p20-p6-red-vitest.log` — the eighteen §6 obligations as vitest tests.**
Run `2026-11-04T04:52:46Z`, exit 1: **13 failed | 9 passed (22 tests)**.

Passed: 1, 2, 3, 4, 4b, 14c, 15, 16, 17 — i.e. every accept-case and every compatibility-case in §5F
already holds, which is what makes the eventual change safe to scope.

**c. `runtime/tmp/p20-redirect.log` — §5D redirect experiment** (two `127.0.0.1` HTTP servers).
Plain fetch and the Conway-built OpenAI client both **followed** a loopback→loopback cross-port
redirect (`COMPLETED -> model=answered-by-B`). A redirect toward the host's LAN IPv4 with nothing
listening failed only because nothing was listening there — it is not a protection.
`redirect:"error"` and a per-hop-validating custom `fetch` each prevented the hop
(`serverB hits=0`). Neither mitigation is present today.

## 14. Residual findings

| ID | Finding | Severity | Evidence | Status |
|---|---|---|---|---|
| **F-20-01** | `normalizeProviders` (`src/inference/provider-registry.ts:543`) admits any `baseUrl` string: no scheme, host, port, userinfo or fragment validation. A configured non-loopback HTTP, `file:`, `data:` or credential-bearing URL becomes a live client. | **HIGH** — prompt content and the environment-sourced key are sent in cleartext to whatever host the file names | `p20-p6-red.log` 30/30; `p20-p6-red-vitest.log` obligations 5–13 | **OPEN, unapproved** |
| **F-20-02** | The same gap exists on the **environment-driven** path: `overrideBaseUrl` (`:265-270`) accepts any URL and is called from `src/agent/loop.ts:181` with `process.env.OPENAI_BASE_URL`, which `loop.ts:170-173` itself sets from `config.conwayApiUrl`. A hostile or stale `OPENAI_BASE_URL` overrides a shipped HTTPS provider with HTTP. | **HIGH** | `overrideBaseUrl("openai","http://evil.example/v1")` → `ACCEPTED`; vitest 14b FAILED | OPEN, unapproved |
| **F-20-03** | An **empty or blank** `baseUrl` is silently rewritten to `https://api.openai.com/v1` (`stringOr` at `:632`, fallback at `:543`). A truncated local config therefore re-points inference at a cloud provider — with a key from the environment — without any error. | **HIGH** — silent provider substitution | vitest 18 FAILED; probe `malformed-empty` | OPEN, unapproved |
| **F-20-04** | `fromConfig` swallows a JSON parse failure and keeps the built-in defaults (`:300-302`), and it **replaces** rather than merges the provider list when ≥1 provider parses (`:284-286`). A corrupted or hostile provider file can therefore change the whole provider set with no signal. The defaults are HTTPS so this is not directly exploitable, but it contradicts §9's intent. | MEDIUM | probe `invalid JSON → ACCEPTED silently, fell back to 4 default providers`; existing shipped test `provider-registry.test.ts:80` asserts the current behaviour | OPEN — recorded, deliberately **not** in the P-6 change (changing it would break an approved test) |
| **F-20-05** | A loopback HTTP URL does not constrain the next hop: both global fetch and the SDK-followed redirect reached a different loopback listener. Validation at construction time cannot cover this; it needs `redirect:"error"` or a per-hop-validating `fetch`. | MEDIUM (the same-class risk toward a non-loopback destination is what §5D forbids) | `p20-redirect.log` | OPEN, unapproved |
| **F-20-06** | Failover covers only HTTP 429/500/503 (`RETRYABLE_STATUS_CODES`, `inference-client.ts:10`, `isRetryableError` `:413-416`). A connection failure, a timeout, a 401/403 or a choice-less 200 aborts the entire tier with **no fallback provider attempted**. §8A asked to verify the registry behaves per its existing policy — it does, and the policy is thin. Availability, not confidentiality. | MEDIUM | `p20-fallback-tests.log` tests 1, 2, 3, 5 | OPEN — recorded; changing it is a separate approval |
| **F-20-07** | **Exposure observation (§10).** `<host-lan-ip>:3001` accepts TCP connections from this host, so FreeLLMAPI is **not** loopback-bound; it listens on an interface reachable from the LAN, subject only to the Windows firewall. Conway binding its client to `localhost` does not change that. This raises the cost of F-20-01: the gateway that an unvalidated HTTP URL would talk to is itself LAN-reachable, and its key handling is not loopback-gated. | **HIGH (contextual)** | `p20-exposure-probe.log` — `127.0.0.1:3001 CONNECTED`, `[::1]:3001 CONNECTED`, `localhost:3001 CONNECTED`, `<host-lan-ip>:3001 CONNECTED`, `127.0.0.1:8787 ECONNREFUSED` | **Recorded only.** §10 forbids modifying FreeLLMAPI; binding it to loopback is the operator's decision |
| **F-20-08** | Dashboard accuracy (§11). `dashboard/server/panels/core.ts:217-278` ("AI Models") is honest about the general rule — a declared model is rendered `NOT VERIFIED … declared, never invoked`, latency and token cost are `UNKNOWN`, and no cell claims a working connection. But it knows nothing about A13: the credential table (`:220-224`) lists only `conwayApiKey`/`openaiApiKey`/`anthropicApiKey`, never `FREELLMAPI_API_KEY` or `inference-providers.json`; and the notice at `:273` still says live testing is pending "because no credential is configured", which predates the provider set that now drives routing. Understating the configuration is not the §11 failure mode (no false green), but the panel cannot answer "which providers would actually be used". | LOW–MEDIUM | file read, lines quoted | OPEN — a dashboard source change needs its own approval (§11) |
| **F-20-09** | FreeLLMAPI's own working tree changed during this window: 14 tracked modifications and 42 untracked files in its git status, including `server/src/db/migrate/defaults.ts` and a new `20261104_000001_septor_output_tokens.ts` migration. Attribution: **not this phase** — no command in this session targeted that tree, and the content concerns a different product concern (Septor output-token limits). Recorded because §16 requires knowing whether the environment moved under the audit. | INFORMATIONAL | `p20-close-invariants.log` (11 files newer than the `04:32:28Z` baseline), `git status --porcelain` counts | Recorded, no action |
